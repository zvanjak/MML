# MML Tolerance Policy

*Normative. Adopted 2026-10-14 (epic MinimalMathLibrary-wewi.4, task 4.1). Companion to
[CONTRACT_POLICY.md](CONTRACT_POLICY.md) (what a method promises) and
[RESULT_POLICY.md](RESULT_POLICY.md) (what a result reports). This document says **which number
a comparison is allowed to use, where that number lives, and how it is spelled.***

Before this policy the library had one correct answer at the root (`PrecisionValues<T>`,
`isNearlyEqual(abs, rel)`) and everything else: `Defaults::*` copies, `Constants::GEOMETRY_EPSILON`
(a type-independent `1e-10` even for `float`), literals (`1e-10`, `1e-14`, `1e-4`, `0.01`, `50000`),
`ε·1000`, `numeric_limits::min()` as a generic "small number", `-1.0` sentinels, exact `== 0` on
computed values, and `DivisionSafetyThreshold` wherever a small constant was needed. The inventory
in `.beads/history/2026-10-14_01_TOLERANCE_INVENTORY.md` (generated by
`testing/tolerance_inventory.py`) lists 1 020 such sites.

---

## 1. The one rule

**A numeric tolerance, threshold, step scale or budget may be written as a literal in exactly one
file: `mml/MMLPrecision.h`.** Everywhere else it is a *named* `Precision::` constant, a config
field that defaults to one, or a problem quantity (norm, dimension, |x|) multiplied by one.

A literal in a comparison is a decision nobody can find, review, or retune. Naming it is the whole
policy; the rest of this document is about which name.

Exceptions (not tolerances): mathematical coefficients (RK tableaux, quadrature nodes/weights,
series/approximation coefficients, physical constants), loop counters, array sizes, and output
formatting. The inventory script allow-lists coefficient tables by file and accepts a
`// tol-ok: <reason>` marker on a line for the rare justified case.

Mathematical coefficients used in `Real` arithmetic must be explicitly typed for `Real`;
an untyped decimal can promote float arithmetic to double and narrow the result afterward.
Retain the supplied digits in reference and coefficient tables rather than adding float
suffixes to shared data. Generic scalar algorithms must use their own scalar or magnitude
type, not the build's `Real`, for conversions and tolerance defaults.

## 2. Vocabulary: tiers and families

`Precision` is `PrecisionValues<Real>`; it has three specializations (`float`, `double`,
`long double`) so every constant scales with the build's `Real`. **`Precision::X` is the canonical
spelling.** `PrecisionValues<T>::X` is for templates over another `T`; `Defaults::X` tolerance
mirrors are deprecated (see §7). `Constants::GEOMETRY_EPSILON` has been removed;
use `Precision::GeometryEpsilon` directly, with no compatibility alias.

**Machine-level** (exact for the type):

| Name | Value (double) | Meaning |
|---|---|---|
| `Eps` | 2.2e-16 | machine epsilon |
| `SqrtEps` | 1.5e-8 | ε^½ — forward-difference step, Brent / golden-section tolerance floor |
| `CbrtEps` | 6.1e-6 | ε^⅓ — 2nd-order central-difference step |
| `FourthRootEps` | 1.2e-4 | ε^¼ — 2nd-order second-derivative step |
| `FifthRootEps` | 7.4e-4 | ε^⅕ — 4th-order central-difference step (`CalcJacobian`) |
| `RoundoffZeroThreshold` | 100·ε ≈ 2.2e-14 | zero up to the roundoff of O(100) flops at unit scale: a norm before normalizing, integer-valuedness of a Real, trailing polynomial coefficients |
| `DivisionSafetyThreshold` | 1e-30 | the only "tiny" constant: denominators below it are unsafe |
| `UnboundedIntervalSamplingLimit` | 1e10 | finite stand-in for ±∞ when an unbounded interval must be sampled |

**Tiers** (the five absolute magnitudes every comparison-family constant is one of):

| Tier | double | float | long double (80-bit) | Use |
|---|---|---|---|---|
| `CoarseTolerance` | 1e-4 | 1e-4 | 1e-4 | fast/preview solver presets; region-level sampling heuristics (field analyzers, conservativeness) |
| `LooseTolerance` | 1e-6 | 1e-6 | 1e-6 | exploratory / sampling checks; user-facing default (`DefaultTolerance`) |
| `ModerateTolerance` | 1e-8 | 1e-6 | 1e-8 | convergence of iterative solvers on well-conditioned problems (`DefaultToleranceStrict`, `NewtonTolerance`) |
| `EqualityTolerance` | 1e-10 | 1e-6 | 1e-15 | two computed values of the same quantity agree (`*IsEqualTolerance`, `GeometryEpsilon`, `IsMatrix*Tolerance`, `OrthogonalityTolerance`) |
| `ZeroTolerance` | 1e-12 | 1e-6 | 1e-15 | a computed quantity is negligible (`NumericalZeroThreshold`, `QuaternionZeroThreshold`, `LinearDependenceTolerance`) |
| `StrictTolerance` | 1e-15 | 1e-6 | 1e-18 | structural zero: pivots, determinants, eigenvalues (`DeterminantZeroThreshold`, `EigenSolverZeroThreshold`) |

Tier ordering is non-strict: float deliberately shares the same value across several tiers.
Tests must not require distinct tier values or use double-only finite ranges and accuracy
requests when running with float. A warning-clean float build is a compilation gate, not
evidence that its numerical runtime tests have passed.

Float regression fixtures must also resolve the numerical operation they exercise: do not
differentiate unresolved spectral tails, request root tolerances below representable spacing,
or use a loose Newton stopping criterion to test a much tighter trajectory contract.
For computed residuals and composed derivatives, account for the problem scale and the
roundoff amplification of the dot products or difference stencils. Outward-rounded enclosing
geometry is checked for containment as well as proximity to the exact radius.
Fixed-step refinement must reduce truncation error above the accumulated roundoff floor;
below it, both resolutions must remain within that floor and the original accuracy limits.
These float-specific checks do not relax the double-precision fixtures.

Fused multiply-add can change a rounded boundary by one ulp without changing the
mathematical expression. Closed-domain fixtures must use the same explicitly rounded
boundary callbacks in their membership guards; independently recomputing a curved
bound is not a portable containment oracle. Keep next-representable out-of-domain
points rejected rather than widening the domain.

Linear-solve residual checks use the componentwise backward-error scale
`|A| |x| + |b|` and a dimension-derived roundoff budget, not a fixed absolute
unit threshold. Float forward-error checks for large reference solutions are
normwise relative and retain a separate backward-error gate; double reference
accuracy remains unchanged. A quadratic central-difference witness can use a
dyadic step for a strict identity check, while its default-step check must also
account for sample and coordinate roundoff amplified by `1/h`.

Offset-variance fixtures must preserve the input variation before accumulation, and
integer-limit fixtures must distinguish the last representable in-range input from
the first out-of-range one. Solver norm helpers retain their element magnitude type
even when the build uses a narrower `Real`, with scaled accumulation for extreme ranges.
CG normalizes search directions before matrix products and uses normalized inner products
and norm ratios instead of underflowing or overflowing squared residuals.
Composed numerical Jacobians propagate both derivative uncertainties through the matrix
products and retain an independent accuracy cap. Order ratios require resolved errors:
the float RODAS4 linear witness resolves fourth order, while its nonlinear near-roundoff
errors retain bounded accuracy and constraint checks; double keeps both order witnesses.

DCT reference transforms evaluate phases and sums in at least double precision, including
the inverse path; high-frequency mode identities check the reference independently of FFT
agreement. Large-count negative-binomial masses use the conditional-Poisson identity with
the existing deviance/Stirling log-mass kernel, rather than subtracting nearly equal
log-gamma values. Widening the final result alone cannot repair either cancellation.
Euler extraction at a gimbal pole assigns the determined combined rotation to one angle.
Tests reconstruct the rotation for both conventions, both poles, and either quaternion
sign instead of demanding a unique singular Euler triple.

Float implicit-retry fixtures need a resolved Newton stopping criterion and an explicit
iteration budget that actually induces retries. Both reused and full-Newton paths must
meet the reference accuracy contract. Work savings remain strict; a double-only percentage
reduction is not required when float BDF2 steps already need few Newton corrections.
Adaptive tolerance-refinement witnesses must use distinct representable requests, and
minimum-step rejection witnesses must have a truncation error above the requested tolerance.

Numerical Jacobian defaults using second-order central differences use `CbrtEps`,
not the forward-difference `SqrtEps`, and divide by the actual representable sample
separation. Kernel zero-limit tests use the dimensionless argument (for sinc, `N*x`),
not an absolute input threshold independent of sharpness. A DAE time tolerance is not
permission to skip a representable final interval: Radau and its BDF4 history/endpoint
use must reach the exact requested endpoint or report failure.

For numerical curvature identities, float checks propagate the derivative stencil's
reported estimates or analytically bounded stencil truncation and roundoff errors,
with a separate accuracy cap on that uncertainty, rather than demanding analytic precision.
Analytic reference curves also check the derivative-error bounds themselves.
Integration error estimates must satisfy the requested absolute-or-relative bound and
need not lie below the roundoff floor. Failure-policy fixtures bound the refinement budget
instead of assuming that a sub-roundoff accuracy request cannot converge.
Periodic rotations are compared by geodesic
distance at the branch cut while still checking the canonical angle range.

Rational interpolation evaluates its correction tableau in at least double precision:
rounded float corrections must not manufacture a pole. Exact nodes, constant data and genuine
poles retain their contracts; reciprocal references cover both node orders and several scales.
Public ODE/map Jacobians use the central-difference `CbrtEps` default and the actual representable
sample separation, with overflow-safe quotients and unchanged explicit relative-step semantics.

Float curve fixtures must keep every analytic derivative finite and nonzero; locally centering
a numerical curve preserves the physical point without an excessive parameter-scaled stencil.
The full Robertson float witness uses the equivalent conserved coordinate `u = x0 + x1`,
reconstructs all physical species, and resolves the terminal minor-species error budget.
It retains the published full horizon, reference accuracy, mass checks and measured solver work;
double keeps the original species coordinates. Oscillatory quadrature requests must exceed the
accumulated roundoff bound, and both the estimate and independent value must meet that request.

**Families** keep their semantic names — `Precision::Vec3CartIsEqualTolerance` documents *what*
is compared — but each is defined as a tier in `MMLPrecision.h`, so retuning a tier retunes the
family. **Algorithm-specific** constants (`ODEDefaultTolerance`, `IntegrationTolerance`,
`OptimizationTolerance` = 3e-8 ≈ 2·`SqrtEps`, `EventTolerance`, `JacobianDelta`, …) are tuned
independently and stay explicit values in the same file.

Adding a constant: put it in all three specializations, pick a tier if it is a comparison, add a
one-line comment saying what it protects.

## 3. The comparison vocabulary (`mml/MMLBase.h`)

Inline tolerance arithmetic is replaced by these; they are the only place the `<` vs `<=` and
abs-vs-rel decisions live.

| Helper | Test | When |
|---|---|---|
| `IsNearlyEqual(a, b, absEps, relEps)` | `|a−b| < absEps + relEps·max(|a|,|b|)` | **default scalar equality**: abs dominates near zero, rel for large values |
| `IsNearlyEqual(a, b, eps = EqualityTolerance)` | same, one tolerance | the common case |
| `IsWithinAbs(a, b, absEps)` | `|a−b| < absEps` | values known to be near zero or on a known scale |
| `IsWithinRel(a, b, relEps)` | `a == b ∨ |a−b| < relEps·max(|a|,|b|)` | both values away from zero; `(0, 0)` is equal |
| `IsNearlyZero(x, eps = ZeroTolerance)` | `|x| < eps` | "this computed quantity is negligible" |
| `IsNegligibleRelativeTo(x, scale, eps = Eps)` | `|x| ≤ eps·|scale|` | pivot vs matrix norm, residual vs ‖b‖, step vs |x| |
| `IsUnsafeDenominator(d)` | `|d| < DivisionSafetyThreshold` | guard before dividing |
| `AnglesAreEqual(a, b, eps)` | wrap-aware `|a−b|` | angles in radians |
| `T::IsEqualTo(b, eps = Precision::TIsEqualTolerance)` | element-wise `IsWithinAbs` | vectors, matrices, points (CONTRACT_POLICY §2) |

Relative vs absolute, decided once:

- **Equality of computed values** → combined (`IsNearlyEqual`). Pure absolute only when the scale is
  structurally known (coordinates on a unit sphere, residuals already normalized).
- **Negligibility of a computed quantity** → relative to the problem scale when a scale exists
  (`IsNegligibleRelativeTo(pivot, norm·n)`), absolute (`IsNearlyZero`) when none does.
- **Convergence** → the config's `tolerance`, interpreted per RESULT_POLICY §4 (`error ≤ tol·|value| +
  floor`), with the floor a `Precision::` constant — never `0.0`, never a literal.
- **Singularity** (pivots, denominators, norms before normalizing) → **always scaled**: `Eps·‖A‖·n`
  for pivots, `DivisionSafetyThreshold` only as the last-resort absolute guard, `Normalized()` throws
  when the norm is below `Precision::RoundoffZeroThreshold` (100 ulp of unit scale).

## 4. Exact comparisons, sentinels, budgets

**Exact `== 0` / `!= 0` on a floating-point value is allowed only for:**

1. *structural / literal inputs*: a user-supplied `h == 0` meaning "choose automatically", a
   coefficient array entry that is zero by construction, a dimension cast to `Real`;
2. *IEEE special handling*: `if (d == 0) throw DivisionByZeroError` before an exact division, sign
   tests, `std::signbit`;
3. *values the code itself set*: comparing against a sentinel it assigned one statement earlier.

Everything computed (a norm, a determinant, a difference, a residual, a derivative) goes through
`IsNearlyZero` / `IsNegligibleRelativeTo`. The inventory's `EXACT_ZERO` category is a review list,
not a bug list — each hit is either reclassified as (1)–(3) or fixed.

**Sentinels.** A `Real` slot never carries `-1.0` (or `-1`) to mean "unavailable". Use
`NoEstimate` (NaN, RESULT_POLICY §3) for estimates, `std::optional<Real>` for optional values, and
the result's `status` for failure. Integer `-1` for "no index" stays an `int`.

**Budgets.** Iteration counts, sample counts, subdivision depths and size caps are config fields
or `Defaults::` runtime context values (`Defaults::BisectionMaxSteps`, …), never bare `50`, `1000`,
`50000` in an algorithm body. `Defaults::` is the right home for *runtime-adjustable* defaults;
`Precision::` for compile-time tolerances.

**Step sizes.** Finite-difference steps are `Precision::<Root>Eps · max(1, |x|)` (never
`std::pow(epsilon, 0.2)` or `std::sqrt(epsilon)` inline); an explicit `h` from the caller is an
absolute step and must be `> 0` and finite or it is rejected.

**`numeric_limits<T>::min()`** is an *underflow* guard (Lentz continued fractions' `fpmin`,
denormal checks on reflector norms), not a tolerance. Any use as "is this negligible?" is a defect.

**Scaled epsilons.** `Eps · <problem quantity>` is the correct form for singularity thresholds. A
pure numeric multiplier (`ε·1000`, `ε·100`) is a tuning literal and must be a named constant in
`MMLPrecision.h` with a comment saying what it compensates for.

## 5. Geometry

One tolerance: `Precision::GeometryEpsilon` (= `EqualityTolerance` in all three scalar
specializations, including extended-precision `long double`). It is a tier alias, not an
independently tuned geometry threshold. The former
`Constants::GEOMETRY_EPSILON` spelling has been removed. Orientation / incidence predicates (`IsPointOnLine`, `IsInside`,
`Intersects`, `IsParallel`) default their `eps` argument to the matching `Precision::*` family
constant and, where a scale exists, test scale-aware (`‖a×b‖ ≤ eps·‖a‖·‖b‖`, see
`Vector3Cartesian::IsParallelTo`). Exact arithmetic predicates (`Orient2D` and friends) are the
exception and say so in their contract.

## 6. Inventory categories and their replacements

`python testing/tolerance_inventory.py [--md out.md] [--dir base|core|algorithms|systems|tools] [--check]`

| Category | What it finds | Replacement |
|---|---|---|
| `SCI_DEFAULT` | `Real eps = 1e-10` default argument | the matching `Precision::` family constant |
| `SCI_COMPARE` | `< 1e-12`, `fabs(x) > 1e-10` | `IsNearlyZero(x, Precision::…)` / `IsNegligibleRelativeTo` / named constant |
| `SCI_OTHER` | literal elsewhere (config defaults, step scales, `h * 1e-10`) | `Precision::` constant; coefficient tables are allow-listed |
| `EPS_SCALED` | `epsilon() * 1000` | named constant or `Eps · <problem quantity>` |
| `TINY_MIN` | `numeric_limits::min()` | keep for underflow guards (named `fpmin`), fix if used as a tolerance |
| `EXACT_ZERO` | `== 0.0` / `!= 0.0` | §4 rules (1)–(3) or `IsNearlyZero` |
| `SENTINEL` | `= -1.0;` / `return -1.0;` in a `Real` slot | `NoEstimate` / `std::optional` / status |
| `DECIMAL_CMP` | `< 0.01`, `> 0.5` in a comparison | named constant (often an algorithmic ratio — name it where it is used, e.g. a `static constexpr` with a comment, or `Precision::` if shared) |
| `INT_BUDGET` | `1000`, `50000` near iteration/size words | config field or `Defaults::` |

`--check` fails on the forbidden categories (`SCI_DEFAULT`, `SCI_COMPARE`, `EPS_SCALED`,
`TINY_MIN` outside allow-listed guards, `SENTINEL`); the review categories are reported only.
After tasks 4.2–4.4 the check runs clean and becomes part of the guard script (wewi.5.7).

## 7. Transition (tasks 4.2 base, 4.3 core, 4.4 algorithms / systems / tools)

- Per subsystem: run the inventory, replace, rerun, keep tests green; where a literal masked a
  defect (a tolerance that was never reachable, a `-1.0` that leaked into arithmetic), add a test.
- The lowerCamel helpers (`isNearlyEqual`, `isWithinRelPrec`, …) are `[[deprecated]]` forwarders
  now; `isWithinRelPrec(0, 0)` used to be `false` — `IsWithinRel(0, 0)` is `true`.
- `Defaults::*IsEqualTolerance` and the other 33 `Defaults::` tolerance mirrors are `[[deprecated]]`
  (4.4, 2026-10-14) - no modular header uses them; `Defaults::` keeps the runtime-adjustable
  `AlgorithmContext` / `PrintContext` values (whose defaults come from `Precision::`).
- Status: `python testing/tolerance_inventory.py --check` passes for the whole of `mml/` (4.2 base,
  4.3 core, 4.4 algorithms / systems / tools / interfaces). Constants added for the former algorithm
  literals are listed in `MMLPrecision.h` under "Algorithm constants"; the three Lyapunov chaos
  thresholds are one `Precision::LyapunovChaosThreshold`.
- `Constants::GEOMETRY_EPSILON` is removed. Migrate directly to `Precision::GeometryEpsilon`;
  there is no alias or forwarding shim. Strict geometry-header compilation rejects deprecated
  call sites on GCC/Clang and explicitly enables C4996 diagnostics on MSVC.
- Sibling repos (MML-Packages, book, MPL) get the deprecation warnings at `/W3`; nothing breaks.

## Checklist for a new or changed comparison

- [ ] Is the number a named `Precision::` constant (or a config field defaulting to one)?
- [ ] Is it the right tier for the question (equal? negligible? structurally zero?)?
- [ ] Is a scale available? Then `IsNegligibleRelativeTo` / `IsNearlyEqual(abs, rel)`, not pure absolute.
- [ ] Is the exact `== 0` justified by §4 (1)–(3)? Say which in a comment.
- [ ] No `-1.0` in a `Real`; no bare iteration budget; no `std::pow(epsilon, …)` inline.
- [ ] Does the inventory `--check` still pass for the touched subsystem?
